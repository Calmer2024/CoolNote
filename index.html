MiraAgent

项目 添加标签
MiraAgent2026.04 · 至今

项目简介：一个支持人设设定、长期记忆与工具调用的陪伴型 Agent，核心是有状态、多轮、可自主调用工具的 Agent Core，具备每会话记忆、目录级别事件与长对话上下文管理能力，并通过 Web 与微信多人入口接入。

技术栈：SpringBoot、MybatisPlus、PostgreSQL + pgvector、pg_search、Skills、MCP、SSE、RAG

主要工作：

  • 身份与风格层：角色卡定义身份，描述式世界书定义全局风格与世界观；注入设定前缀，维护长对话人设与命中前缀缓存。
  • 三层记忆架构：会话记忆、压缩摘要、长期记忆三层递进；长期记忆以文件为事实源，数据库建索引，检索重注入。
  • 混合检索：长期记忆 bm25 + 向量双路召回、RRF 融合与类目重排，多规模检索评测 Recall@5 90%+、Top-1 78%+。
  • 压缩即学习：流水线上下文压缩，压缩时由 LLM 同步提炼关键事实并异步写入长期记忆，主链路零阻塞。
  • 后台经验复盘：满足条件才触发，独立线程异步回放，复盘产物落 Skill 或记忆；记忆写入按相似度去重后覆盖。
  • 自动化评测：将工具调用率、意图识别延迟、回复质量（LLM-as-Judge）等指标化，全链路 trace 可观测。

介绍一下这个项目

MiraAgent 是一个支持人设、长期记忆和工具调用的陪伴型 Agent。核心不是套壳调用 API，而是一个有状态、多轮、能自主调用工具的 Agent Core。开发途中我主要围绕人设稳定性、记忆召回质量、长上下文压缩和工具执行可靠性展开。

在角色设计上，系统通过角色卡维护身份与表达风格，通过世界书补充背景事实。每轮对话会根据场景选择需要注入的设定，而不是把所有资料一次性塞入上下文，从而控制 Token 消耗并减少无关信息干扰。

整体架构与技术栈

服务端使用 Spring Boot 承载会话编排，PostgreSQL 保存业务数据，pgvector 与全文检索共同组成混合召回。Agent 通过 MCP 接入工具，使用 SSE 向前端持续返回思考状态、工具事件和最终回复。

设计目标不是让模型记住所有内容，而是在需要的时候找到正确的内容，并以可控方式重新注入上下文。

长期记忆是怎么实现的？

记忆层将短期上下文、阶段摘要和长期事实分离。短期上下文保证当前对话连贯；阶段摘要控制上下文长度；长期事实经过归一化、去重和索引后持久化。检索时同时使用关键词和语义向量，然后使用 RRF 合并排序结果。

技术栈里的 RAG 如何落地？

系统先基于会话意图生成查询，再从角色记忆、项目资料和工具结果中分别召回候选内容。候选项经过权限过滤、时间衰减和相关性重排后，作为结构化上下文提供给模型。

MCP 和 SSE 分别解决什么问题？

MCP 统一工具发现与调用协议，SSE 负责将执行过程以事件流推送给客户端。两者组合后，用户可以看到检索、工具执行与答案生成的完整过程。

遇到的最困难部分

最困难的是在召回率、响应速度与记忆污染之间取得平衡。最终通过异步写入、分层索引、置信度阈值和可回放评测集，让系统能够持续迭代而不牺牲主链路体验。
