# CoolNote 设计规范

版本：1.6 · 2026-08-15

## 1. 规范关系

- 产品 UI/UX 以 `product-prototype-demo.html` 为视觉与交互真源。
- 组件行为与复用边界遵循 `component-system.md`。
- 本文件规定所有页面必须遵守的通用设计底线。

## 2. 图标

- 不使用任何 Unicode 字符或 Emoji 充当操作图标；用户主动选择的“心情”属于内容数据，可使用 Emoji 呈现。
- 图标只能来自 `assets/lucide-icons.svg` 或后续确定的同一图标库。
- 缺少图标时先补充图标库，再通过 `<svg><use></use></svg>` 使用。
- 图标按钮必须设置 `aria-label`，并在需要时显示 Tooltip。
- 同一动作在导航、菜单、批量栏和 Toast 中使用相同图标。
- 图标一般与相邻文本字号相当；菜单图标可比文字大 1–2px，但必须保持基线和视觉中心对齐。
- 删除、关闭等辅助图标可比相邻文本小 1–2px，但必须保持清晰可辨。
- 文字字符只用于文字内容，不得用 `＋`、`×`、`…`、`✓`、箭头或其他符号模拟控件图标。

## 3. 控件

- 应用内菜单、选择器、输入和确认不得使用 `prompt`、`confirm` 或裸 `select`。
- 高频操作就近显示；低频操作进入 Menu、Popover 或 Dialog。
- Hover、Selected、Focus、Disabled、Loading 和 Danger 状态必须明确。

### 3.1 Tooltip

- 所有仅图标按钮必须提供 `aria-label`，并由全局自绘 Tooltip 呈现该名称；禁止依赖操作系统或浏览器原生 `title` 气泡形成不一致样式。
- Tooltip 使用深灰色高对比背景、白色文字、7px 圆角、6px × 9px 内边距、12px 字号和轻量阴影；浅色与暗色主题保持同一视觉语义。
- 鼠标悬停延迟 360ms 出现，键盘聚焦立即出现；离开、失焦或按下操作后及时消失。
- Tooltip 必须采用锚点定位，默认位于触发按钮上方居中并保持 8px 间距；空间不足时翻转到下方，并始终限制在视口 8px 安全边距内。
- Tooltip 不接收指针事件，不遮断按钮操作；动画仅使用 120ms 的透明度与 2px 位移，并遵守 `prefers-reduced-motion`。
- 文案应直接描述动作，通常不超过 12 个汉字；存在快捷键时可写为“动作 · 快捷键”。

### 3.2 下拉菜单与上下文菜单

- 所有动作型下拉菜单以笔记条目“更多”菜单为唯一几何基准，不允许页面自行定义紧凑版、宽松版或顶部栏专用尺寸。
- 菜单宽度为 224px，最大宽度为 `视口宽度 - 16px`；外层内边距 6px、圆角 10px、1px 中性边框，使用统一 Popover 阴影。
- 标准菜单项最小高度 35px、水平内边距 9px、图标与文字间距 9px、圆角 6px；文字和主语义图标一律左对齐。
- 仅尾部箭头、快捷键或状态说明允许使用 `margin-left:auto` 靠右；不得因图标恰好是最后一个子元素而把整项推向右侧。
- 带副说明的新建菜单允许将单项最小高度扩展为 44px、垂直内边距 5px；菜单宽度、外层内边距、圆角、水平内边距和对齐规则不变。
- 分隔线高度 1px、四周间距 5px；危险操作保持相同行高和对齐，仅使用 Danger 语义色区分。
- 菜单默认与触发按钮保持 6px 锚点间距；支持 Light Dismiss、`Esc`、视口避让与上下翻转，滚动或缩放时持续跟随触发锚点。
- 菜单进入动效统一为 180ms 的透明度与 5px 位移；必须遵守 `prefers-reduced-motion`。

### 3.3 浮层关闭与定位

- 所有下拉菜单、上下文菜单、选择器、命令菜单、搜索结果、链接输入、公式输入和其他非模态浮层，必须支持点击浮层与触发锚点之外的区域立即关闭；`Esc` 同样关闭当前最高层浮层。
- 所有由光标、选区或控件触发的浮层必须相对触发位置锚定，随滚动、窗口缩放和内容布局变化重新定位，并进行视口边缘避让；禁止以页面固定坐标模拟就近浮层。
- 公式输入框显示在触发公式命令的光标旁边；确认后回到编辑器并渲染公式，取消或点击外部不写入内容。
- 同一交互区域只保留一个主浮层；打开互斥浮层时先关闭旧浮层。

## 4. 布局与反馈

- 操作入口必须靠近作用对象，不跨区域放置。
- Hover 与 Selected 的点击区域和高亮范围保持一致。
- 列表、分类树的名称、数量和操作列必须稳定对齐。
- 可撤销操作使用 Toast；阻断操作使用 Dialog。
- 动效只解释状态变化，并支持 `prefers-reduced-motion`。
- 所有内容列表侧栏标题栏复用同一基准：标题为 17px、700 字重、深色文字；数量为 13px、500 字重、灰色文字，与标题保持 9px 间距并沿同一基线对齐。该规则适用于“收藏”“归档”“回收站”“小记”等内容列表或资源模块；“分类”等分组标签不属于该标题层级。
- 内容列表条目的 Hover 操作必须复用“小记”资源树的基准：操作按钮为 28px 方形、6px 圆角、默认透明背景与低对比图标；条目 Hover 或 Focus Within 时显示，普通操作使用当前 Accent Token，删除操作使用 Danger Token。不得为单个业务列表另造尺寸、渐变遮罩或不同显隐方式。
- 原地新建条目只显示语义图标与名称输入框，不显示重命名、删除或其他 Hover 操作；容器与输入框必须设置 `min-width:0` 并限制在列表可用宽度内，任何新建态都不得触发横向滚动条。
- 画廊封面 Hover 操作组位于右上角 14px，使用 4px 组内边距、10px 圆角、无边框的半透明浅色背景和模糊；单个按钮高 30px、7px 圆角、12px 文字和 14px 图标，不得挤占封面主视觉。
- 列表条目的 Hover 操作不得使用包裹多个按钮的灰色背景容器；外层保持透明，仅允许当前被 Hover 的单个按钮显示语义色背景。
- 资源列表的数量与 Hover 操作共用尾部空间时，显示操作必须同时隐藏数量；进入原地重命名状态后不渲染任何 Hover 操作图标。
- 画廊标题、介绍和图片墙必须共用同一内容 Gutter Token，输入控件清除浏览器默认内边距，以保证左边线严格对齐。
- 单行大字号标题输入框不得直接使用与字号过于接近的默认行高；必须为 `g`、`p`、`q`、`y` 等英文下伸字形保留额外垂直空间，并以实际渲染后 `scrollHeight <= clientHeight` 作为无裁剪验收条件。
- 画廊图片墙按横向行优先排列，每行最多 3 张；可用宽度不足时响应式降为 2 列或 1 列，不得出现第 4 列。
- 同一内容列表标题栏内的新建、加载/刷新和排序按钮必须共用同一按钮尺寸、图标尺寸与默认颜色，不得为加号单独设置视觉规格。
- Tab 切换必须播放统一的过渡动画，并在分类 Tab 等复用同一 DOM 的视图中可重播；不得为制造动画强制卸载编辑器或丢失未保存状态，并必须遵守 `prefers-reduced-motion`。
- 笔记标题下方的元信息使用低对比度小字号：左侧仅显示用户选择的心情 Emoji，不附加文字；中间使用细分隔线；右侧按“今天修改”“昨天修改”或“YYYY年M月D日修改”显示最近修改日期。
- 心情选择器固定为 6 列、5 排 Emoji，所有网格单元必须允许收缩，卡片不得产生横向溢出。
- 侧边导航项中的数量使用同样的 13px、500 字重和灰色，但固定在导航项右侧的统一对齐线上并垂直居中。选中态只改变标题和图标的语义色，不改变数量的字号、颜色和位置。

### 4.1 修改时间与延迟重排

- 打开、阅读、聚焦或切换到笔记不得更新 `updated_at`；只有标题或正文进入 Dirty State、内容成功持久化且与数据库现有内容确有差异时，才更新修改时间与 revision。
- 心情、收藏、归档、分类等独立元数据操作不得伪装成正文修改，不得改写笔记的正文修改时间。
- 当前笔记处于阅读或编辑状态时，笔记列表顺序必须锁定；保存结果只更新卡片数据，不得在原列表内即时重排，避免视觉跳变。
- 仅在切换到另一篇笔记、离开当前分类或列表视图、用户点击刷新按钮，或执行全局搜索时，重新查询并应用“按修改时间”排序。

### 4.2 滚动条

- 所有可滚动区域使用同一套全局滚动条，不允许业务模块自行设置颜色、宽度或轨道长度。
- 滚动条槽宽和槽高为 10px，滑块通过 2px 透明边框保持约 6px 的可见粗细；圆角必须为胶囊形。
- 纵向轨道上下、横向轨道左右各保留 24px 空白，使滚动条视觉长度短于内容容器，避免贴满面板边缘。
- 滑块最小长度为 28px；浅色主题默认使用 `#E3E7EB`，Hover 使用 `#D3D9DF`，保持低对比、淡化且仍可辨识。
- 暗色主题使用 `rgba(148,163,184,.24)`，Hover 提升至 `.38`；轨道始终透明，不绘制额外边框。
- 滚动条不得覆盖内容，局部列表优先配合 `scrollbar-gutter:stable`，避免出现时引发布局抖动。

### 4.3 Toast 反馈

- 所有工作区（包括笔记、小记、画廊）必须复用共享的 `ProductToast`，通过应用层统一的 `onToast`/`showToast` 入口触发。
- 禁止在功能模块内自行实现固定定位的 Toast、成功提示或错误提示。需要新增语义时扩展共享 Toast 的 tone、图标映射或 `ProductProgressToast`，不得在业务样式表中复制 Toast 外壳。
- 可撤销操作继续使用共享 Toast 的 8 秒撤销入口；普通提示默认 3 秒关闭。错误使用 `error` tone 和 `alert` 语义。
- 所有 Toast 必须自行定时消失，计时器不得因父组件重渲染而重置；业务专用的进度反馈仅可在任务执行期间常驻，完成或取消后默认 3 秒自动关闭，并仍提供手动关闭入口。
- Toast 或进度反馈中的进度条不得绘制边框；使用当前工作区 Accent Token 表示已完成部分，以中性 Surface Token 表示剩余部分。

## 5. 产品语义色

- 普通笔记工作区使用蓝色 Accent Token，不得被“小记”的主题色污染。
- “小记”界面统一使用独立紫色 Token，覆盖 `accent`、`accent-hover`、`accent-soft`、`accent-line`、`focus-ring`、`tag-bg` 和 `tag-text`。
- “小记”的导航选中、资源树 Hover/Selected、按钮 Hover、输入 Focus、Popover 选中和其他强调状态必须引用紫色 Token，不得直接引用普通笔记的蓝色值。
- 紫色 Token 仅在“小记”工作区作用域内覆盖；离开“小记”后必须恢复普通笔记的蓝色 Token。
- 删除、错误和危险操作继续使用 Danger 红色，不受“小记”紫色 Token 覆盖。
- 收藏视图使用黄色语义色：选中态文字与图标使用黄色，背景使用浅黄色，不得使用普通笔记的蓝色选中背景。
- 画廊入口与画廊工作区使用橙色语义 Token；入口、列表选中态、按钮 Hover、输入 Focus 与批量操作反馈必须引用同一橙色色族。
- 功能语义色必须在浅色与深色主题下成对定义，不得由业务组件用临时硬编码颜色覆盖。

## 6. 验收

- 扫描页面不得发现 Emoji 或 Unicode 操作图标替代物；笔记心情数据除外。
- 图标引用必须能在统一图标库中解析。
- 鼠标与键盘均可完成主要流程。
- 浅色、深色和减少动画模式下保持一致。
- 分别检查普通笔记、“小记”和画廊的计算样式，确认蓝色、紫色与橙色 Token 不发生跨工作区泄漏。
