# CoolNote 性能修复与复测

2026-10-15，当前工作区开发版。修复针对调查中已经复现的保存、列表查询、列表渲染、搜索及全文序列化瓶颈。此前的页面记忆、表格和置顶改动均保留。

## 改动

- 恢复文件通过有界 BufWriter 序列化，显式 flush 后仍执行 sync_all 和文件替换。新增大文档“数据库提交前失败→草稿完整可读→原 revision 不变→重试成功→清理草稿”的回归测试。
- 列表查询按是否指定分类、是否搜索生成明确条件；正常视图直接按 is_pinned 排序，回收站沿用时间排序。增加分类/删除状态/归档状态/置顶/更新时间联合索引。分类、排序切换立即请求，仅输入搜索继续防抖。
- 超过 160 条时采用按实际行高测量的虚拟列表，保留视口及预加载行；置顶分区、复选框、菜单、加载更多、方向键、Home/End 和外部选中定位继续可用。复用日期格式器和分类 Map，摘要限制为 240 个 UTF-16 单元并避免切断代理对；分页按 ID Set 去重。
- 搜索使用字符边界填充后的 trigram 索引，**单字、双字及更长中文子串都可命中索引**，同时保留英文大小写、emoji 和原有 LIKE 校验语义。先探测最近 256 篇，应对高频命中词；不足上限时查询完整索引，避免遗漏旧笔记。各类型候选按更新时间合并。前端同时只允许一个搜索请求在途，并只保留最新待执行请求。
- JSON 与 Markdown 快照按不可变 ProseMirror 块缓存，重新序列化发生变化的块；字数统计移出每次 React 渲染，随防抖快照更新。单元测试验证编辑、撤销、标题变化时快照等价及旧快照不被修改。
- 恢复原性能 gate 的数据夹具，增加分类、罕见词、常见词、中文短词查询；长文档读写增加 30 次采样，保存 P95 门禁统一收紧至 100ms。浏览器对照工具对大列表设置 80 行 DOM 上限、16ms 选中更新预算，超标直接报错。

## 同机结果

硬件与数据规模见原调查。后端为 release；前端为 production 构建组件，不能替代整机 WebView2 的端到端延迟。

| 项目 | 修复前 | 修复后 |
|---|---:|---:|
| 5,000 短段落完整保存 | 单次 672 / 686ms | 首次 51.79ms；30 次 P95 **45.36ms** |
| 单段 10 万汉字完整保存 | 单次约 15ms | 30 次 P95 **37.10ms**，仍低于 100ms；新索引有额外维护成本 |
| 10 万篇大分类列表查询 | P95 393.61ms | P95 **15.49ms** |
| 无结果长关键词搜索 | 笔记 SQL 部分 P95 202.30ms | Workspace 服务 P95 **0.92ms** |
| 单字及双字无结果查询，各一次合计 | 原来需 LIKE 扫描 | 10 万篇库，30 次合计 P95 **0.45ms** |
| 5,000 条列表选中渲染，同页固定视口 A/B | P95 217.6ms，5,000 行 DOM | P95 **0.5ms**，21 行 DOM |
| 5,000 段快照，同页对照 | 完整 JSON/normalize/Markdown P95 13.6ms | 缓存预热后，每次修改一块的快照 P95 **1.0ms** |

注意：保存前后采样方式不同，已分别标明单次与 P95；搜索前值仅为笔记 SQL 部分、后值为服务调用，不应当作严格等口径的整机搜索 A/B。列表基线是审计目录中复原的优化前组件，双方均使用 290×800 布局，采样间等待两帧；不包含打开正文、IPC 和保存。增量快照数字不包括字数统计和 IPC。前端 A/B 期间卸载前一组后留出间隔，避免把大列表卸载计入下一组装载时间。

## 数据迁移和边界

新增 schema 18 的列表索引、schema 19 的字符子串索引。已有库首次升级会在事务中建立一次索引，耗时和额外磁盘空间随正文规模增加；不改写笔记正文、标题或 revision。子串索引通过外部内容视图引用原表，并由应用注册的确定性 SQLite 编码函数维护。测试验证 schema 17 与早期开发 schema 18 均可升级。

包含 `%` / `_` 的通配符查询以及 NUL 查询继续走兼容路径，未承诺这类查询也有相同加速。其他模块的全文索引、任务/小记全量快照、历史版本保留策略、首屏依赖拆分仍属于原报告中尚未量化的容量风险，本次没有据此进行大范围重构。原生冷/热启动、输入法到屏幕延迟、总内存和长期泄漏仍不能由本次组件/服务测试宣称达标。
