# Tab 切换专项修复

## 复现与根因

生产构建整页 App，隔离 localhost 数据，笔记与小记各 1000 段、30 个任务，四个 Tab 循环 12 次。此前的列表与数据库局部测试没有覆盖这条链路。

- 原实现每次离开 Tab 卸载整个工作区，返回时重新创建 Tiptap 编辑器、解析正文和加载模块快照。基线笔记和小记 DOM 复用次数均为 0。
- 页面切换重播 200ms 淡入；列表入场动画和网格列宽过渡也增加视觉等待。
- 基线笔记显示内容中位 107.8ms，动画全部结束中位 318.3ms；小记分别为 73.1ms、277.7ms。原始数据见 `tab-before.json`。

## 修复

- `RetainedWorkspace` 首次访问才挂载，返回时复用 DOM、草稿和滚动位置。隐藏时冻结父组件传入的更新，本地自动保存仍可运行。
- 可见性上下文停用隐藏笔记/小记快捷键、笔记布局监听、画廊大图快捷键、模板预览及共享浮层。
- 去掉整页淡入、列表入场和主网格列宽动画；保留按钮颜色、菜单等局部交互反馈。
- 原有笔记离开前序列化、保存及保存失败阻止导航的逻辑保留。

## 验证与限制

- 第一阶段实测笔记显示内容中位降为 40.8ms、小记 25.5ms；笔记复用 12/12，小记首次加载后的返回复用 11/11。见 `tab-after.json`。此时尚未移除列表入场和网格列宽动画，因此这不是最终视觉完成耗时。
- 最终实现循环测试再次确认相同复用次数，检测到的有限动画仅为导航按钮的颜色过渡。见 `tab-final-throttled.json`。
- 最终计时部分受到浏览器后台节流影响，出现约 1 秒的帧间隔；该轮耗时不能用于性能对比。未宣称原生桌面端达到特定毫秒预算。基准新增帧间隔检查，后续运行会标出并排除受节流样本。
- `npm run build` 通过，包含 95 项前端测试、类型检查和全部前端契约检查。新增 3 项回归覆盖按需挂载、DOM/草稿保留、隐藏期间本地状态更新、恢复最新属性、隐藏浮层及快捷键清理。
- 当前桌面开发进程保持运行，改动已由开发服务器热更新。尚未发布或更新已安装的正式版。

保留页面会增加已访问模块的常驻内存，当前最多保留一个笔记编辑器和一个小记编辑器；没有为全部文档建立缓存。原生长期内存占用尚未量化。

复现：`npx vite build scripts/tab-performance --config scripts/tab-performance/vite.config.ts`，再以同配置运行 `vite preview`，使用隔离端口。该页面会清空自身 origin 的 Web 演示数据，请勿部署至实际数据所在 origin。
