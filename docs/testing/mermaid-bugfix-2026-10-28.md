# 文本绘图拖放与 Mermaid 错误隔离

## 复现步骤

### 源码拖放

1. 在笔记中插入文本绘图，保留源码区域可见。
2. 在源码框中输入 `graph TD` 和下一行 `A-->B`。
3. 用鼠标选中 `A`，再从选中文字上开始拖动，在源码其他位置松开；同时检查按住 Ctrl 拖动的情况。
4. 检查源码是否重复插入，以及笔记是否新增整个绘图模块。

修复前源码框只通过 NodeView.stopEvent 隔离编辑器事件，没有取消浏览器原生拖放。绘图外层又是 draggable 节点，拖动还可能以外层节点作为事件目标。

修复后取消源码区域的 dragstart、dragover、drop；源码框聚焦期间，也取消外层收到的 dragstart。普通鼠标选字、键盘编辑和复制粘贴不受这些事件处理影响。源码选区拖放不再用于移动或复制文字。

自动化回归在真实 Tiptap NodeView 上派发可取消的拖放事件，断言事件被取消、选区不变、源码和文档不变、编辑器未进入模块拖动状态。该测试验证事件处理，未模拟操作系统级鼠标拖动。

### 页面底部的 Mermaid Syntax Error

1. 在笔记中插入文本绘图。
2. 将源码改为 `graph TD` 和下一行 `A[unfinished`，等待渲染。
3. 同一笔记中再放一个有效图表 `graph TD` 和下一行 `A-->B`，以及普通正文。
4. 检查窗口底部及图表外部是否出现大幅 Syntax error in text 图形。

编辑过程中暂时删去括号也能触发该问题。真实 Mermaid 11.16.1 的回归测试在修复前观察到 body 多出一个错误图形容器，修复后只剩编辑器容器。

根因是默认 render 未传入容器，Mermaid 在 body 中创建临时 SVG；语法异常路径抛出异常时会保留错误 SVG。应用捕获异常并在图表内显示提示，并不能清理 Mermaid 已经产生的外部 DOM。

修复为每次渲染传入独立的屏外临时容器，启用 suppressErrorRendering，并在 finally 中移除该容器。错误提示仍由当前图表区域显示。初始化与渲染作为完整任务串行执行，避免全局配置在其他渲染过程中被重置。源码变化时立即失效旧任务的结果，避免旧语法错误覆盖新源码。

## 验证

`npm run test:mermaid` 覆盖源码拖放取消、多图表全局配置隔离、过期错误忽略，以及真实 Mermaid 的错误隔离、有效流程图渲染、正文编辑和修正为有效时序图后的恢复。

真实 Mermaid 测试只补齐 jsdom 缺少的 SVG 文本尺寸测量，不替换 Mermaid 的解析与渲染逻辑。已加入 `test:editor`，随正常构建运行。
