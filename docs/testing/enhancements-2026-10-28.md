# 标题切换、阅读位置与拼音搜索

## 行为

- Ctrl+1～5 应用对应标题级别，再次按同级快捷键恢复正文；不同级别直接切换。Ctrl+6 直接恢复正文。Ctrl+N 保持新建笔记。
- 笔记、小记分别按内容 ID 保存阅读位置到本机工作区存储，切换内容、切换工作区和重开应用后恢复。首次打开从顶部显示。
- 恢复优先使用正文块 ID，其次使用附近相同文字的段落，再按原段落序号选择相邻位置；超出滚动范围时限制在末尾，无正文块时按滚动比例回退。延迟加载的图片、字体和图表引起布局变化时，会重新定位；用户开始交互后停止自动定位。
- “/”菜单和全局搜索保留原文字匹配，增加中文名称的无声调全拼、首字母、大小写、空格和拼音分隔符匹配。支持多音字读音组合，避免只采用默认读音漏掉常见名称。
- 桌面全局搜索覆盖笔记、小记、任务、子任务、任务清单和画廊名称；正文仍使用原文字搜索。搜索在服务端候选筛选和限制结果数量之前完成，不依赖前端当前加载的列表。

## 手动验收

1. 在笔记和小记正文中分别连续两次按 Ctrl+1，再测试 Ctrl+2～5；第二次应恢复正文。切换不同级别应保留文字。
2. 打开较长笔记 A，滚动至中部；切换至首次打开的笔记 B，B 应显示顶部；返回 A 应恢复原位置。
3. 对两条长小记重复上述操作。切换笔记、小记工作区及关闭重开开发程序，检查各自位置仍然独立。
4. 在已记录位置之前插入或删除段落，再次打开，应尽量恢复原段落。删除原段落或大幅缩短内容后，应落在相邻段落或新的末尾。
5. 打开含有大图片或 Mermaid 图表的长文，检查延迟加载后的定位，以及开始滚动后不会被拉回。
6. 在“/”菜单输入 `wenbenhuitu`、`WBHT`，应找到文本绘图；输入 `daima` 应找到代码块。
7. 创建“项目计划”“生活记录”“重新命名”等名称，分别使用 `xiangmujihua`、`XMJH`、`sheng huo ji lu`、`cxmm` 搜索。检查名称重命名后搜索立即变化、删除内容不出现在结果中。

## 自动化

- `editorShortcuts.test.ts` 验证五级标题的反复切换及不同级别切换。
- `readingPosition.test.tsx` 验证持久化、切换、首次顶部、工作区隐藏恢复、正文变化回退和延迟图片布局。
- `searchMatch.test.ts` 验证前端匹配与浏览器全局搜索。
- Rust `infrastructure::search_match::tests` 验证真实 SQLite 服务路径，包括各类资源名称、结果限制、重命名、删除和多音字。

前端测试均已加入 `npm run build` 的 `test:editor`；Rust 测试通过 `npm run rust:test` 运行。自动化阅读位置验证采用 jsdom 的模拟布局，仍需通过桌面端完成实际视觉与鼠标验收。

拼音接口依据 [pinyin-pro 文档](https://pinyin-pro.cn/use/pinyin.html) 与 [Rust pinyin 文档](https://docs.rs/pinyin/latest/pinyin/) 实现。
