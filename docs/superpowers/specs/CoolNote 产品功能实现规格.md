# CoolNote 产品功能实现规格

版本：1.0  
日期：2026-08-11  
状态：已确认，供产品、设计、研发和测试共同使用

## 1. 文档目的

本文档定义 CoolNote 从静态 UI Demo 进入正式开发后需要实现的完整产品能力、功能边界、业务链路、实现程度、数据关系、异常处理、性能目标和发布门禁。

本文档中的“支持”不代表只完成界面或理想流程。标记为 GA 的功能必须具备持久化、异常恢复、性能、可访问性、日志、自动化测试和升级兼容能力，能够长期保存真实个人资料。

## 2. 产品定位

CoolNote 是面向个人用户的生产级 Windows 本地笔记系统，用于长期写作、知识整理、资料管理、任务追踪和日程安排。

核心原则：

- 本地运行：笔记、附件、索引、版本和备份均保存于用户本机。
- 离线完整：核心功能不依赖账号、服务器或网络。
- 数据可靠：编辑、升级、迁移、删除和恢复均有明确的数据安全边界。
- 性能可扩展：以 10 万篇笔记和百万内容块为设计规模。
- 数据可迁移：支持标准格式导入导出，不制造无法迁移的数据孤岛。
- 个人优先：不引入团队、权限、共享和协作复杂度。

### 2.1 目标用户

- 需要长期积累个人知识的普通用户。
- 需要记录学习、项目、工作和生活资料的个人用户。
- 需要在笔记中管理任务、提醒和日程的个人用户。
- 需要离线保存敏感或重要资料，但首版不要求数据库加密的用户。

### 2.2 正式支持范围

- Windows 10 22H2。
- Windows 11 当前受支持版本。
- x64；ARM64 在完成专项验证后作为 GA-受控能力发布。
- 本地 NTFS 笔记库。
- 中文、英文、数字和代码内容混合使用。

### 2.3 明确不实现

以下能力不进入首版数据模型和业务链路：

- 账号体系。
- 云同步和云备份。
- 团队空间、成员、权限、共享、评论和协作编辑。
- 画板、白板、手写和专业绘图。
- 网页剪藏和浏览器扩展。
- 数据库加密、主密码、Windows Hello 和自动锁定。
- 云端 AI、在线语义检索和在线 OCR。
- 首版本地 AI 功能。

## 3. 实现程度定义

| 等级 | 定义 | 发布要求 |
|---|---|---|
| GA-完整实现 | 首个正式版本的生产能力 | 正常流程、异常流程、性能、恢复、可访问性和自动化测试全部完成 |
| GA-受控实现 | 首版正式提供但限制范围 | 限制必须在 UI 和帮助中明确展示，不允许伪装成完整能力 |
| Post-GA 增强 | 首版不提供入口 | 可预留扩展点，但不得增加首版核心复杂度 |
| 不实现 | 产品明确排除 | 不建设业务数据模型、后台任务和隐藏入口 |

任何仅完成静态页面、内存状态、演示数据或理想流程的能力均不算实现。

## 5. 核心数据模型

所有实体使用稳定 UUID。路径、标题和显示名称不得作为业务主键。

### 5.1 笔记库 Library

关键字段：

- `id`
- `name`
- `root_path`
- `format_version`
- `created_at`
- `last_opened_at`
- `last_clean_shutdown_at`
- `settings_json`

规则：

- 每个笔记库拥有独立数据库、附件、恢复日志、索引和配置。
- 同一时间一个应用实例只激活一个写入笔记库。
- 用户可创建、打开、切换、迁移和关闭多个笔记库。
- 默认笔记库首次启动自动创建。

### 5.2 分类 Category

关键字段：

- `id`
- `parent_id`
- `name`
- `icon_name`
- `color`
- `sort_order`
- `created_at`
- `updated_at`
- `deleted_at`

规则：

- 支持多层嵌套，数据结构不限制层级。
- 同一父级允许同名，通过完整路径区分。
- 禁止将分类移动到自身或其后代节点下。
- 用户可自定义名称、Lucide 图标和颜色。
- 系统维护“未分类”，用户不可永久删除。

### 5.3 笔记 Note

关键字段：

- `id`
- `category_id`
- `title`
- `document_json`
- `plain_text`
- `schema_version`
- `content_hash`
- `revision`
- `is_favorite`
- `is_pinned`
- `is_archived`
- `created_at`
- `updated_at`
- `deleted_at`

规则：

- 每篇笔记只能归属一个分类。
- 笔记可拥有多个标签。
- 正文事实源为规范化编辑器 JSON，同时保存纯文本派生数据。
- 搜索索引、摘要和缩略图均为可重建派生数据。

### 5.4 内容块 Block

每个顶层块至少包含：

- `block_id`

- `attrs`
- `content`
- `sort_position`

### 5.5 标签 Tag

## 6. 核心业务链路

### 6.1 创建与编辑

```text
新建笔记
→ 生成 UUID 和初始数据库记录
→ 打开编辑器
→ 内存 Transaction
→ 增量保存
→ 同事务更新正文、任务和链接索引
→ 异步更新全文索引与列表摘要
```

要求：

- 新建后立即可输入。
- 自动保存不得阻塞输入线程。
- 切换笔记、关闭窗口和退出前强制提交。
- 保存失败时保留内存草稿和恢复日志。
- UI 明确展示保存状态，不得静默失败。

### 6.2 分类与标签

```text
新建/移动分类
→ 校验名称、父节点和循环引用
→ 单事务更新分类树
→ 刷新侧边栏、面包屑和筛选条件
```

删除分类前展示子分类、笔记、任务和附件影响。用户可迁移内容，或将整棵分类树移入回收站。

### 6.3 搜索

```text
输入查询
→ 解析关键词和结构化条件
→ 取消旧查询
→ 查询全文索引与结构化字段
→ 综合排序
→ 返回高亮片段
→ 点击定位到具体块
```

索引不可用时降级为基础数据库搜索，并提示后台重建。

### 6.4 任务与日程

```text
插入任务块
→ 保存任务属性
→ 更新任务索引
→ 出现在日程视图
→ 注册本地提醒
→ 通知点击定位原笔记块
```

笔记进入归档或回收站后默认停止提醒。恢复后重新计算未过期提醒。

### 6.5 删除与恢复

```text
删除笔记
→ 标记进入回收站
→ 普通视图与提醒移除
→ 保留版本和附件引用
→ 恢复或永久删除
→ 延迟清理无引用附件
```

### 6.6 异常恢复

```text
异常退出
→ 启动检测不完整会话
→ 回放恢复日志
→ 比较数据库 revision
→ 自动恢复或展示选择
```

数据库完整性失败时进入只读安全模式，禁止继续写入原库。

### 11.2 存储规则

- 文件实体使用 SHA-256 内容哈希命名。
- 写入流程为临时文件、哈希校验、原子重命名。
- 相同内容只保存一个实体文件。
- 单附件至少支持 2GB。
- 超大文件允许作为外部链接引用。
- 删除附件引用后先进入待清理区，不立即物理删除。

## 16. 推荐技术架构

### 16.1 技术栈

- Tauri 2 + Rust：桌面外壳和本地核心服务。
- React + TypeScript：UI。
- Tiptap/ProseMirror：块级编辑器。
- SQLite：唯一事实源。
- SQLite FTS5：可重建全文索引。

### 16.2 分层

```text
React UI / Tiptap
        │
类型化 Commands / Events
        ▼
Rust Application Core
  ├─ Library Service
  ├─ Note Service
  ├─ Editor Save Service
  ├─ Search Service
  ├─ Task Service
  ├─ Attachment Service
  ├─ Version/Backup Service
  └─ Import/Export Service
        │
        ▼
SQLite + Attachments + Recovery Logs
```

约束：

- 前端不直接执行 SQL。
- 前端不拥有任意文件系统权限。
- 所有写操作经过 Rust 服务层和数据库事务。
- SQLite 使用 WAL、外键和单逻辑写入服务。
- 多窗口读取可并行，业务写入按优先级串行。
- 正文、任务和内部链接同事务提交。
- 搜索索引、摘要和缩略图最终一致且可重建。
- 数据库、编辑器 Schema 和导出格式分别版本化。
- 不启动本地 HTTP 业务服务。
- 不引入协作 CRDT、插件运行时或 AI sidecar。

## 18. 安全、隐私与可访问性

### 18.1 安全

- HTML 导入和富文本粘贴使用白名单清理。
- 禁止脚本、事件处理器和危险 URL。
- 外部协议使用明确允许列表。
- 文件路径规范化，并校验最终目录范围。
- 导入包防止路径穿越、符号链接逃逸和压缩炸弹。
- 更新包必须验证签名。
- CoolNote 不以管理员权限运行。

### 18.2 隐私

- 默认不上传任何笔记、附件、日志和崩溃数据。
- 日志不记录正文。
- 诊断包由用户主动生成，生成前展示内容。
- 更新检查属于可关闭的产品更新请求，不传输笔记库内容。

### 18.3 可访问性

- 所有主要操作具备键盘路径。
- 图标按钮提供可访问名称和工具提示。
- 支持系统缩放 100%–300%。
- 支持高对比度和减少动画。
- 颜色对比达到 WCAG AA 目标。
- 保存状态和错误使用非侵入式 live region。

## 23. 完成定义

CoolNote 首个正式版本完成的判断标准不是“页面能操作”，而是：

- 用户能够创建真实笔记库并长期写作。
- 编辑、分类、标签、搜索、任务、附件和日程形成闭环。
- 删除、异常退出、升级、数据库损坏和磁盘不足均有可恢复路径。
- 用户能够把全部数据导出为标准格式，并能够从备份恢复。
- 10 万篇笔记规模下核心操作达到性能目标。
- 所有 GA 功能具备自动化测试、错误提示、日志和维护入口。
- 产品不存在无效导航、演示数据依赖或仅保存在内存中的正式功能。

满足以上条件后，CoolNote 才可定义为生产级个人笔记系统。
