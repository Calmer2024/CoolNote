# CoolNote 任务工作区设计

**状态：** 已完成需求逐项确认，等待用户审阅本文档并批准实施
**分类：** 架构级（Architectural）
**日期：** 2026-08-15

## 1. 背景与目标

CoolNote 需要在全局侧边栏“小记”下方新增一级入口“任务”。该模块是一个本地优先、单用户的任务管理子系统，交互参考飞书任务的多列表格，但减少协作、自定义字段和复杂视图能力，保持 CoolNote 当前克制、清晰的桌面端设计风格。

用户应能用任务清单组织顶层任务，在收集箱快速记录未归类任务，通过表格编辑时间、重要程度和备注，通过一层轻量子任务拆分工作，并通过全局月历查看全部带日期任务。

附件中的飞书截图只作为功能密度和布局参考，不作为额外产品指令，也不要求逐像素复刻。

## 2. 已确认的产品边界

### 2.1 用户与数据边界

- 首版仅服务个人、本地单用户。
- 不包含账号、成员、负责人、指派、关注、活动动态、多人协作或云同步。
- 不为上述协作能力预留字段或空接口。
- 桌面端数据存入 CoolNote 当前 SQLite 笔记库。
- 浏览器开发模式使用与桌面端等价的本地持久化契约，不使用模拟数据。

### 2.2 任务清单

用户创建的任务清单包含：

- 必填名称。
- 必选图标；创建时提供默认任务清单图标，之后可更换。
- 可选多行纯文本备注。

任务清单不包含“目标”字段，不在数据库、契约或界面中预留该字段。清单图标从 CoolNote 现有图标库选择，不允许单独设置颜色，统一使用任务模块的绿色强调 Token。

系统“收集箱”不是数据库中的普通任务清单。顶层任务的清单 ID 为空时即属于收集箱；收集箱不可重命名、删除或更换图标。

### 2.3 顶层任务

每个顶层任务包含：

- 必填标题。
- 可选多行纯文本备注。
- 可选开始时间。
- 可选截止时间。
- 四级重要程度：紧急、重要、普通、低；默认值为普通。
- 完成状态及完成时间。
- 可选所属任务清单；为空表示收集箱。
- 在所属范围内的人工排序位置。
- 零个或多个轻量子任务。

开始时间和截止时间分别支持“仅日期”或“日期加具体时刻”。仅日期值保持日期语义，不转换成午夜时间。两者同时存在时，截止不得早于开始。

### 2.4 子任务

子任务只包含：

- 必填标题。
- 完成状态。
- 在父任务内的人工顺序。

子任务不包含时间、重要程度、备注或所属清单，也不能创建下级子任务。数据结构必须从数据库层面阻止三级嵌套。

父任务和子任务完成状态相互独立。完成父任务不会修改子任务；父任务完成后整组进入“已完成”，展开后仍能查看和勾选尚未完成的子任务。子任务不会被提升为顶层任务，也不会在普通视图重复出现。

## 3. 方案选择

采用独立任务垂直切片，不复用笔记或小记数据模型，也不先重构通用工作区框架。

选择该方案的原因：

- 任务具有独立的状态、时间、排序和父子关系，强行放入内容模型会造成长期耦合。
- 现有小记、画廊和全局样式存在用户未提交修改，本次应降低交叉改动。
- 画廊已验证“前端工作区、共享契约、Tauri 命令、Rust 服务、SQLite 迁移、Web 存储”的垂直切片方式。
- 少量工作区协调代码重复比本轮重构多个既有模块更安全，符合 YAGNI。

明确不采用：

- 先抽取小记、画廊和任务共用的工作区框架。
- 把任务存成特殊笔记或小记。
- 只制作前端原型、使用临时数据或延后持久化。

## 4. 总体架构

### 4.1 前端

在 `AppMode` 中增加任务模式，并在全局侧边栏把“任务”放在“小记”正下方、“画廊”上方。

新增独立 `TaskWorkspace`，负责加载任务快照、当前范围、任务视图与日历视图、筛选、排序、详情抽屉、保存状态和错误反馈。内部按职责拆分为：

- 任务模块侧边栏。
- 任务清单标题与备注区域。
- 任务表格与表格行。
- 子任务列表。
- 基础筛选工具栏。
- 月历。
- 任务详情抽屉。
- 日期、重要程度和清单选择浮层。

共享组件继续使用 `Icon`、`FloatingLayer`、`ProductDialog`、`ProductToast` 和全局 Tooltip。任务模块不使用浏览器原生 `alert`、`prompt` 或 `confirm`。

### 4.2 后端

Rust 侧新增独立任务领域模型、任务应用服务和 Tauri 命令模块。任务服务负责：

- 快照查询和单项查询。
- 清单、任务、子任务的创建与更新。
- 完成状态变更。
- 范围内排序和任务移动。
- 软删除与限时撤销。
- 日期和层级校验。
- 任务相关搜索。

任务服务不得依赖笔记、小记或画廊服务。全局搜索服务只负责汇总各领域返回的搜索结果。

### 4.3 Web 开发模式

浏览器模式增加与 Tauri 命令一一对应的任务存储函数。快照返回副本，避免 React 状态直接修改持久化对象。Web 模式必须实现相同的校验、修订冲突、软删除、撤销、排序和搜索语义。

## 5. 数据模型

新增迁移版本 13，包含以下表。字段命名可遵循仓库现有 Rust/SQLite 约定，但语义必须保持一致。

### 5.1 `task_lists`

- `id`：唯一标识。
- `name`：非空名称。
- `icon_name`：已注册图标名称。
- `notes`：纯文本备注，默认为空字符串。
- `sort_order`：任务模块侧边栏中的人工顺序。
- `revision`：乐观并发修订号。
- `deleted_at`、`delete_token`：软删除与撤销。
- `created_at`、`updated_at`。

### 5.2 `tasks`

- `id`：唯一标识。
- `task_list_id`：可空外键；为空表示收集箱。
- `title`：非空标题。
- `notes`：纯文本备注，默认为空字符串。
- `start_value`、`start_precision`：可空开始值及 `date`/`datetime` 精度。
- `due_value`、`due_precision`：可空截止值及 `date`/`datetime` 精度。
- `importance`：`urgent`、`important`、`normal`、`low`，默认 `normal`。
- `is_completed`、`completed_at`。
- `sort_order`：收集箱或所属清单内的人工顺序。
- `revision`：乐观并发修订号。
- `deleted_at`、`delete_token`：软删除与撤销。
- `created_at`、`updated_at`。

### 5.3 `task_subtasks`

- `id`：唯一标识。
- `task_id`：指向顶层任务的非空外键。
- `title`：非空标题。
- `is_completed`、`completed_at`。
- `sort_order`：父任务内的人工顺序。
- `revision`：乐观并发修订号。
- `deleted_at`、`delete_token`：随父任务删除与恢复。
- `created_at`、`updated_at`。

子任务表不包含 `parent_id` 或对子任务表自身的外键，因此不存在表达三级嵌套的路径。

### 5.4 约束与索引

- 清单名称和任务标题去除首尾空白后不能为空。
- 清单允许重名，任务也允许重名。
- `start_precision` 和 `due_precision` 只能在对应值存在时出现。
- 日期与日期时间比较由领域服务使用统一规则完成，数据库保存规范化值。
- 为活动清单顺序、清单内活动任务顺序、完成状态、日期范围、删除令牌和子任务父键建立必要索引。
- 清单 ID 指向已删除或不存在的清单时拒绝写入，不自动改入收集箱。

## 6. 导航与视觉规范

### 6.1 全局入口

“任务”是独立一级入口，顺序为“小记、任务、画廊”。任务入口采用独立的任务语义图标 `list-todo`，不得复用其他一级入口图标。图标通过 CoolNote 的统一 `Icon` 基础组件注册和渲染。

### 6.2 绿色任务 Token

任务模块使用专属绿色强调 Token，覆盖：

- “任务视图 / 日历视图”Tab 选中态和下划线。
- 当前任务范围的选中态。
- 任务模块主要创建按钮和必要的焦点强调。
- 任务清单图标。

普通文字、分隔线、中性背景、危险操作和四级重要程度颜色继续使用全局或各自语义 Token。任务模块不得整体染绿。

四级重要程度采用固定语义色：紧急为红色、重要为橙色、普通为蓝色、低为中性灰色。颜色必须同时配合文字或图标，不得成为唯一信息载体。

### 6.3 工作区布局

任务模式保持三栏：

1. CoolNote 全局侧边栏。
2. 任务模块侧边栏。
3. 任务表格或日历主区域。

任务模块侧边栏支持与小记、画廊一致的折叠体验。主区域切换 Tab 时沿用 CoolNote 统一过渡动画，并尊重减少动画设置。

## 7. 任务模块侧边栏

固定系统入口依次为：

1. 收集箱。
2. 全部任务。
3. 今天。
4. 已完成。

其下显示用户任务清单。清单项展示图标、名称和未完成顶层任务数量。任务清单可创建、重命名、编辑图标与备注、手动调整顺序和删除。

所有数量只统计顶层任务，不把子任务重复计数：全局侧边栏“任务”显示全部未完成顶层任务总数；收集箱和具体清单显示各自未完成数；“今天”显示逾期与今天相关任务去重后的数量；“已完成”显示已完成顶层任务数。

系统入口不可重命名、删除、换图标或拖入用户清单区域。

删除非空任务清单前，`ProductDialog` 明确展示将一并删除的顶层任务和子任务数量。确认后清单、任务和子任务使用同一个删除令牌软删除；不把任务移入收集箱。

## 8. 任务视图

### 8.1 顶部区域

右侧主区域顶部提供“任务视图 / 日历视图”Tab。

选中具体任务清单时，标题区域常驻显示清单图标、可编辑名称和可折叠多行备注。备注折叠状态只属于界面偏好，可在本地持久化。系统入口显示固定标题与简短说明，不显示可编辑清单备注。

### 8.2 表格列

固定核心列为：

- 完成状态。
- 任务标题；备注作为标题下方常驻文本，不建立备注列。
- 开始时间。
- 截止时间。
- 重要程度。
- 所属清单。

“所属清单”列只在全部任务、今天和已完成中显示，在收集箱和具体任务清单中隐藏。首版不支持配置、隐藏或调整列顺序。

备注为空时不保留空白备注行；存在备注时显示合理行数的摘要，完整内容可在详情抽屉编辑。备注不是仅在 Hover 或抽屉打开时才可见。

### 8.3 行与详情抽屉

标题、开始时间、截止时间、重要程度和所属清单支持表格内直接编辑。点击任务标题同时选中任务并打开右侧详情抽屉。

详情抽屉包含：

- 完整标题与完成状态。
- 开始时间、截止时间和重要程度。
- 所属清单。
- 完整备注编辑区。
- 子任务管理区。
- 删除入口。

抽屉关闭后表格恢复完整可用宽度；在较窄窗口中抽屉覆盖主区域而不是把表格压缩到不可用宽度。

### 8.4 子任务

父任务行显示子任务展开按钮和完成数量。子任务默认折叠，用户可逐项展开；展开状态属于当前界面会话，不写入领域数据。

展开区支持新建、改名、勾选、人工排序和删除子任务。子任务不显示时间、重要程度、备注或清单选择器，也不存在添加下级任务的入口。

### 8.5 创建规则

- 在具体任务清单中新建时自动归入当前清单。
- 在收集箱中新建时保持清单 ID 为空。
- 在全部任务、今天或日历中新建时默认进入收集箱，同时允许在创建界面立即改选任务清单。
- 从日历某天创建时预填该日期；用户可在提交前改为开始日期、截止日期或完整区间。
- 新建行未输入标题便失焦或按 Esc 时取消，不产生空记录。

## 9. 范围、排序和筛选

### 9.1 系统范围

- 收集箱：未完成且清单 ID 为空的顶层任务。
- 全部任务：所有未完成顶层任务，不按清单分组。
- 今天：先显示未完成逾期任务，再显示开始日期、截止日期或完整日期区间涉及本地今天的未完成任务。
- 已完成：所有已完成顶层任务及其子任务组。
- 具体清单：该清单内未完成顶层任务。

普通范围默认隐藏已完成任务。基础完成状态筛选允许用户临时重新显示完成任务，但不会改变系统入口的默认语义。

### 9.2 人工排序

只有收集箱和具体任务清单支持顶层任务拖拽排序。任务在清单间移动后追加到目标范围末尾。

全部任务、今天和已完成是跨清单范围，不支持拖拽，也不保存额外视图顺序。子任务只在同一父任务内拖拽排序。

### 9.3 字段排序

所有任务表格范围支持按开始时间、截止时间和重要程度排序。字段排序生效时，收集箱和具体清单也暂停拖拽；切回“自定义排序”后恢复人工顺序。

无日期值稳定排在有日期值之后；重要程度顺序固定为紧急、重要、普通、低。相同字段值使用人工顺序和 ID 保证稳定结果。

### 9.4 基础筛选

支持组合筛选：

- 完成状态。
- 重要程度。
- 日期状态：逾期、今天、未来、无日期。

筛选状态只作用于当前任务视图，不创建或保存自定义视图，不支持复杂逻辑表达式。

日期状态使用以下确定规则：

- 逾期：未完成且存在截止值；仅日期截止早于本地今天，或具体截止时刻早于当前时刻。只有开始值而没有截止值的任务永不判定为逾期。
- 今天：开始日期等于今天、截止日期等于今天，或同时存在开始和截止且区间覆盖今天。具体截止时刻已经过去的任务可以同时属于“今天”和“逾期”。
- 未来：任务不涉及今天且至少一个尚未到达的开始或截止值位于今天之后。
- 无日期：开始和截止值都为空。

多个重要程度选项之间使用“或”，多个日期状态之间使用“或”，不同筛选类别之间使用“且”。

## 10. 日历视图

首版只提供全局月视图，始终汇总全部任务清单和收集箱中带日期的顶层任务，不受任务表格当前清单范围影响。

显示规则：

- 同时存在开始和截止日期时，以跨日条覆盖完整日期区间。
- 只有开始日期时，只显示在开始日期。
- 只有截止日期时，只显示在截止日期。
- 日期时间任务仍按其本地日历日期落位，并在文本中显示具体时刻。
- 无日期任务不出现在月历。
- 已完成任务以弱化样式显示，但仍保留在对应日期，避免月历历史突然消失。

月历支持上月、下月和返回今天。点击任务打开详情抽屉；点击日期打开新建任务界面并预填日期。首版不支持拖拽改期、拖动边缘调整区间、周视图或日视图。

当同一天任务过多时，单元格显示有限数量并提供“还有 N 项”入口，在浮层中查看当天剩余任务，避免无限撑高月份网格。

## 11. 保存与数据流

进入任务模块时加载任务清单、顶层任务和子任务快照。前端基于该快照派生系统范围、筛选结果、排序结果和月历数据，不为各视图保存重复任务副本。

常用表格字段在用户明确提交单元格后保存。备注输入使用短防抖保存；切换任务、切换视图、关闭抽屉或离开任务模块前强制刷新待保存备注。

任务和清单更新携带基础修订号。后端只在修订号匹配时写入并递增修订号。子任务编辑同样使用修订号，避免两个窗口或异步响应静默覆盖。

前端可以乐观更新明确、可回滚的字段。持久化失败时恢复到最后成功值，并显示错误 Toast。备注保存失败时保留当前草稿，显示失败状态和重试入口，不得用旧值覆盖用户仍在编辑的文本。

日期校验在前端和后端各执行一次。日期比较采用用户本地时区；仅日期与日期时间混合比较时，以所选日期的自然边界解释：开始日期为当天开始，截止日期为当天结束。

## 12. 完成与删除

完成父任务只改变父任务的 `is_completed` 和 `completed_at`。子任务状态不变。重新打开父任务也只改变父任务状态。

删除单个任务采用操作菜单中的二段式确认，不使用居中弹窗；删除任务清单使用 `ProductDialog`。删除顶层任务时，其全部子任务使用同一令牌软删除。

删除成功后显示 8 秒撤销 Toast。撤销在数据库事务中恢复清单、任务、子任务、原归属和原排序。应用重启后不保证 Toast 或撤销入口继续存在，但仍处于撤销保留期的数据可以由后续清理策略处理，不在普通查询中显示。

删除令牌过期或恢复失败时不得报告成功。软删除记录的最终清理可使用与现有画廊一致的延迟清理策略，不增加任务回收站界面。

## 13. 全局搜索

CoolNote 顶部全局搜索扩展以下内容：

- 顶层任务标题。
- 顶层任务备注。
- 任务清单名称。
- 子任务标题。

任务结果显示任务类型、标题、备注摘要或所属清单以及更新时间。点击顶层任务结果后进入任务模块，选择合适范围并打开详情；点击子任务结果后定位父任务并自动展开子任务；点击清单结果后进入该任务清单。

已软删除内容不参与搜索。已完成任务可以被搜索到，定位后进入已完成范围。顶部搜索框文案和无结果状态同步加入“任务”。

## 14. 错误处理与可访问性

- 空清单名称和空任务标题不允许提交。
- 已有名称或标题被清空时恢复最后成功值并保留编辑焦点。
- 非法时间区间显示行内错误，阻止提交。
- 不存在或已删除的目标清单拒绝移动。
- 修订冲突停止覆盖，重新读取最新记录并提示用户基于最新内容继续编辑。
- 数据库或 Web 存储失败时回滚可回滚的乐观状态。
- 备注保存失败时保留草稿并允许重试。
- 删除和撤销失败提供明确错误信息。
- 加载时显示忙碌状态；空清单、空筛选结果和无日历任务分别显示对应空状态。
- 最高层浮层响应 Esc，关闭后焦点返回触发元素。
- 所有图标按钮、完成框、拖拽入口、Tab 和日期操作具备可访问名称和键盘路径。
- 减少动画设置下关闭非必要切换动画。

## 17. 完成定义

本次任务模块只有同时满足以下条件才算完成：

- 用户可以创建、编辑、排序和删除真实持久化任务清单。
- 用户可以在收集箱和清单中完整管理真实持久化顶层任务。
- 顶层任务支持时间、四级重要程度、常驻备注和一层轻量子任务。
- 任务表格、基础组合筛选、规定范围内的排序和拖拽行为正确。
- 月历汇总全部带日期任务，并支持查看、新建和编辑。
- 今天、已完成、父子任务独立完成、删除与撤销符合本文语义。
- 全局搜索可以定位任务、子任务和任务清单。
- Tauri 与浏览器开发模式行为一致，应用重启或页面重载后数据仍存在。
- 错误不会导致已有任务或当前备注草稿静默丢失。
- 自动化测试、构建门禁和人工验收全部通过。
- 现有笔记、小记和画廊没有阻断性回归。
