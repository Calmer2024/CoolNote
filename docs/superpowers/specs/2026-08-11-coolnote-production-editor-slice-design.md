# CoolNote 生产级编辑闭环设计

日期：2026-08-11  
状态：待用户书面复核  
上位规格：`docs/superpowers/specs/CoolNote 产品功能实现规格.md`

## 1. 目标

本阶段把现有静态 UI Demo 转换为可运行的 Windows 本地桌面应用，并交付第一个能够保存真实资料的生产级垂直闭环：用户可以创建或打开本地笔记库，创建笔记，编辑标题和正文，自动保存，关闭并重新打开应用后继续编辑；保存失败或异常退出时能够恢复未提交草稿。

本阶段不是完整 GA。它覆盖产品规格中的“阶段 0：工程和数据底座”以及“阶段 1：生产级编辑闭环”的最小可独立验收子集，后续分类、标签、搜索、任务、日程、完整附件、版本差异、备份、导入导出和发布工程继续按独立里程碑实施。

## 2. 范围

### 2.1 本阶段实现

- Tauri 2 + Rust + React + TypeScript 桌面工程。
- Windows x64 开发、构建和测试路径。
- 默认笔记库的首次创建、再次打开和基础元数据读取。
- SQLite 数据库、迁移、WAL、外键和单逻辑写入服务。
- `Library`、`Note` 和恢复日志所需的最小数据模型。
- 真实笔记列表、当前笔记选择、新建笔记、标题编辑和正文编辑。
- 规范化编辑器 JSON 为正文事实源，纯文本、摘要和大纲为派生数据。
- 顶层块稳定 UUID；本阶段支持段落、一级至三级标题、无序列表、有序列表、任务列表、引用和代码块。
- 大纲根据标题块实时生成，点击后定位对应块。
- 300–500ms 输入防抖后的增量自动保存；切换笔记和退出前强制提交。
- 保存状态：`正在保存`、`已保存`、`保存失败`、`已恢复草稿`。
- 保存失败时保留内存草稿并写入库内恢复日志；下次打开时进行恢复判定。
- 明暗主题与跟随系统三种模式；初始视觉严格继承现有 Demo。
- 笔记列表栏折叠、大纲折叠、键盘选择笔记和基础无障碍名称。
- Rust 单元/集成测试、React 组件测试和创建—编辑—重启恢复的端到端测试。

### 2.2 明确延后

- 分类树和标签的增删改；本阶段所有笔记归入系统“未分类”。
- 搜索、收藏、置顶、阅读模式、分栏、更多菜单的业务实现。
- 图片、普通附件、PDF、音视频和 Office 文件。
- 任务日期、日程、提醒和 Windows 通知。
- 版本历史 UI、块级差异、备份和灾难恢复中心。
- 导入、导出、更新、托盘、快速记录、多窗口和 ARM64。

延后功能不得伪装成已实现能力。对应入口应隐藏或显示明确的“后续里程碑”禁用状态；规格明确“不实现”的“画板”入口从正式 UI 删除。

## 3. 架构

```text
React UI + Tiptap
        │
类型化 Tauri Commands / Events
        ▼
Rust Application Core
  ├─ LibraryService
  ├─ NoteService
  ├─ SaveCoordinator
  └─ RecoveryService
        │
        ▼
SQLite + recovery/ 日志目录
```

前端只持有当前编辑会话和展示状态，不直接访问 SQLite 或任意文件路径。所有持久化写操作通过 Rust 服务层进入同一个按顺序执行的写入通道。数据库是已提交笔记的唯一事实源；恢复日志只保存数据库尚未确认提交的编辑事务，成功提交后清除对应日志。

## 5. 数据模型

### 5.1 Library

首阶段字段：

- `id TEXT PRIMARY KEY`
- `name TEXT NOT NULL`
- `root_path TEXT NOT NULL UNIQUE`
- `format_version INTEGER NOT NULL`
- `created_at TEXT NOT NULL`
- `last_opened_at TEXT NOT NULL`
- `last_clean_shutdown_at TEXT`
- `settings_json TEXT NOT NULL`

默认库目录包含：

```text
library-root/
├── coolnote.db
├── recovery/
├── attachments/
└── library.json
```

`attachments/` 在本阶段只创建目录和边界，不实现附件业务。

### 5.2 Note

首阶段字段与上位规格一致：

- `id TEXT PRIMARY KEY`
- `category_id TEXT NOT NULL`
- `title TEXT NOT NULL DEFAULT ''`
- `document_json TEXT NOT NULL`
- `plain_text TEXT NOT NULL`
- `schema_version INTEGER NOT NULL`
- `content_hash TEXT NOT NULL`
- `revision INTEGER NOT NULL`
- `is_favorite INTEGER NOT NULL DEFAULT 0`
- `is_pinned INTEGER NOT NULL DEFAULT 0`
- `is_archived INTEGER NOT NULL DEFAULT 0`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`
- `deleted_at TEXT`

本阶段创建不可删除的系统“未分类”分类，以满足外键和后续迁移兼容性；前端不开放分类管理。

### 5.3 文档 JSON

文档采用版本化 JSON：

```json
{
  "schemaVersion": 1,
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "attrs": { "blockId": "stable-uuid" },
      "content": []
    }
  ]
}
```

每个顶层块必须有稳定 `blockId`。读取旧 Schema 时先迁移到当前版本，再交给编辑器；未知节点不得静默删除，而应阻止覆盖并显示可恢复错误。

## 6. 创建与编辑数据流

### 6.1 启动

1. Rust 确定默认笔记库路径。
2. 不存在时原子创建目录、数据库和初始迁移。
3. 检查格式版本、数据库完整性标志和恢复日志。
4. 返回库元数据、笔记列表和需要恢复的编辑会话。
5. React 渲染真实数据；空库显示空状态，不注入 Demo 笔记。

### 6.2 新建笔记

1. UI 请求 `create_note`。
2. Rust 生成 UUID、初始空文档、内容哈希和 revision 1。
3. 单事务插入笔记并返回完整 DTO。
4. UI 选择新笔记并立即聚焦标题或正文。

### 6.3 自动保存

1. 编辑器产生本地 transaction 并立即更新 UI。
2. 前端生成包含 `note_id`、`base_revision`、标题、文档 JSON 和客户端事务 ID 的保存请求。
3. 请求发出前，恢复服务先原子写入恢复日志。
4. Rust 校验 Schema、稳定块 ID、revision 和负载大小。
5. 单事务更新正文、纯文本、内容哈希、revision 和更新时间。
6. 提交成功后返回新 revision，并删除已确认的恢复日志。
7. revision 冲突时禁止盲目覆盖，返回冲突错误并保留草稿。

同一笔记在任一时刻只允许一个在途保存请求。新输入在请求期间继续进入下一批，不阻塞编辑器输入。

### 6.4 切换和退出

切换笔记、窗口关闭和应用退出均触发 `flush`。只有数据库确认提交或恢复日志确认安全落盘后才允许完成切换/退出。操作超过限定时间时显示明确状态，不虚假标记为已保存。

## 7. 恢复策略

恢复日志使用临时文件写入、刷新和同目录原子重命名，文件名只使用经过校验的笔记 UUID。日志包含库 ID、笔记 ID、base revision、客户端事务 ID、标题、文档 JSON、内容哈希和创建时间，不包含任意外部路径。

启动时：

- 日志 revision 与数据库一致且内容不同：提示并默认恢复为编辑草稿，用户保存后形成新 revision。
- 日志内容已在数据库中：静默清除重复日志。
- 数据库 revision 已领先：不得自动覆盖，提供“查看恢复草稿”和“保留当前版本”选择。
- 日志损坏：隔离文件并显示诊断信息，数据库内容保持可读。

本阶段的恢复能力针对未提交编辑事务，不替代后续版本历史和自动备份。

## 8. UI/UX

`http://127.0.0.1:4173/#` 当前页面是视觉事实源。React 实现必须保持以下基线：

- 顶部栏高度、左侧固定导航宽度、笔记列表宽度、文档区和大纲比例。
- 品牌蓝、灰阶、圆角、阴影、Noto Sans SC 字体和 Lucide 图标体系。
- 当前笔记的蓝色竖线激活态。
- 文档工具栏跨越正文与大纲；笔记列表由工具栏唯一按钮控制折叠。
- 大纲按钮折叠前后都使用 Lucide `list-tree`。
- 大纲与正文不使用卡片或强分隔线。
- 最侧边栏固定，不提供折叠。

业务化调整：

- 删除“画板”。
- Demo 笔记和数量替换为数据库内容。
- 搜索、日程、收藏、回收站、置顶、收藏、阅读、分栏和更多等未实现能力不允许执行假交互。
- 标题成为真实可编辑输入；空标题显示“无标题笔记”。
- 正文使用 Tiptap 编辑区域，阅读排版尽量复用现有视觉参数。
- 保存状态通过 `aria-live="polite"` 暴露，失败状态同时使用文字与图标，不能只依赖颜色。
- 所有图标按钮保留工具提示和可访问名称。

## 9. 错误处理

| 场景 | 行为 |
|---|---|
| 默认库无法创建 | 显示可复制的错误摘要和重试，不进入伪正常页面 |
| 数据库被占用 | 提供重试和只读诊断信息，本阶段不实现正式只读模式 |
| 数据库损坏 | 停止写入并保留原文件，提示后续恢复路径 |
| 磁盘空间不足 | 停止数据库写入，尽力保留内存草稿和恢复日志，不显示已保存 |
| Schema 不支持 | 禁止覆盖原文档，保留原始 JSON 并显示错误 |
| revision 冲突 | 保留本地草稿，重新加载数据库版本并提示冲突 |
| 恢复日志损坏 | 隔离损坏日志，继续以数据库内容只读展示并提示诊断 |

日志不得记录标题或正文，仅记录错误类别、实体 UUID、revision、耗时和操作结果。

## 10. 测试与验收

### 10.1 Rust

- 迁移可在空库执行且重复启动不会重复应用。
- 外键、WAL 和写入事务正确启用。
- 新建笔记生成稳定 UUID、合法初始文档和 revision 1。
- 保存同时更新 JSON、纯文本、哈希和 revision。
- 旧 revision 保存被拒绝且不会覆盖新内容。
- 数据库提交成功后恢复日志被清除。
- 模拟提交失败时恢复日志仍存在。
- 损坏恢复日志不会覆盖数据库内容。
- 文件名和路径校验阻止目录穿越。

### 10.2 React

- 空库、加载、错误和正常列表状态。
- 新建笔记后立即进入编辑。
- 标题为空时显示“无标题笔记”。
- 编辑 transaction 触发防抖保存，切换笔记触发强制保存。
- 保存状态转换和 `aria-live` 输出正确。
- 大纲由真实标题块生成，点击定位正确块。
- 笔记列表和大纲折叠保持现有无障碍契约。
- 未实现入口不可产生假状态。

### 10.3 端到端

1. 启动空库。
2. 新建笔记并输入标题、标题块、段落和列表。
3. 等待显示“已保存”。
4. 完全关闭并重新启动应用。
5. 验证笔记列表、标题、正文、块 ID 和大纲均恢复。
6. 注入一次保存失败，验证状态为失败且恢复日志存在。
7. 重新启动，验证恢复草稿可见且不会覆盖更新版本。

### 10.4 视觉验收

在 1920×1080、1440×900 和 1280×720 下与现有 Demo 对比：

- 主要区域尺寸和对齐无肉眼明显漂移。
- 字体、颜色、图标、圆角和留白保持一致。
- 编辑状态、空状态、保存失败和恢复提示不破坏工作区层级。
- 笔记栏折叠后宽度为零，大纲在窄窗口按现有规则隐藏。

## 11. 性能边界

- 编辑器输入处理不等待 Tauri command。
- 保存内容在后台序列化和提交，普通笔记保存目标 P95 不超过 100ms。
- 笔记列表首阶段采用分页接口，不一次把全文加载到前端。
- 当前笔记打开只返回该笔记的完整文档；列表 DTO 只含标题、摘要、时间和状态。
- 不使用持续轮询；保存、状态和后台结果通过 command 返回与事件驱动更新。

首阶段性能测试至少覆盖 10,000 篇笔记的列表分页和一篇 5,000 块文档的打开、输入与保存。完整 100,000 篇目标在后续性能里程碑进入 GA 门禁。

## 12. 安全与权限

- Tauri capability 只开放本阶段明确使用的命令。
- 前端不获得通用文件系统或 Shell 权限。
- 所有库路径由 Rust 规范化并验证范围。
- 文档 JSON 和粘贴 HTML 使用允许列表；脚本、事件处理器和危险 URL 不进入编辑器 Schema。
- 应用不以管理员权限运行。

## 13. 完成定义

本阶段完成必须同时满足：

- 应用是 Tauri 桌面应用，不依赖本地 HTTP 业务服务。
- 页面显示真实 SQLite 数据，不依赖 Demo 数组或 LocalStorage。
- 用户可创建、编辑、自动保存并在重启后继续编辑笔记。
- 保存失败、revision 冲突和异常退出均不会静默丢失草稿。
- 未实现功能没有伪交互，画板入口已删除。
- 自动化测试、构建和三种桌面视口的浏览器/应用视觉验收通过。
- 数据库和恢复日志格式均有明确版本，未来迁移不依赖标题或路径作为主键。
