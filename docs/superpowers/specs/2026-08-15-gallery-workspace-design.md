# CoolNote 画廊工作区设计

日期：2026-08-15  
状态：已批准并完成首版实现  
分类：架构级（Architectural）

## 1. 背景与目标

CoolNote 在侧边栏“小记”正下方新增独立一级入口“画廊”。画廊用于积累图片灵感、整理参考素材，并在应用内展示个人作品。

首版只支持图片，不支持视频、网页、SVG、HEIC、AVIF、OCR 或图片级文字。所有画廊处于同一层级，不提供父子目录。灵感参考和个人作品集不区分类型，统一由画廊名称、画廊介绍和图片内容表达用途。

本功能必须形成真实的本地持久化闭环，不得只有静态界面或仅保存在 React 内存中。

## 2. 范围

### 2.1 包含

- 独立一级“画廊”导航入口。
- 可折叠的平级画廊列表。
- 画廊创建、重命名、删除和人工排序。
- 画廊名称及可换行纯文本介绍。
- JPEG、PNG、WebP、GIF 图片导入。
- 文件选择器批量导入和 Tauri 文件拖放导入。
- 每行最多三张的响应式图片墙、人工图片排序和增量加载。
- 应用内灯箱浏览。
- 图片复制到系统剪贴板和另存为原图。
- 单图及批量删除、移动、复制。
- 跨画廊图片复用和物理文件去重。
- 导入进度、取消、部分成功和错误汇总。
- 画廊名称及介绍的全局搜索。
- 深色模式、减少动画、键盘操作和现有产品浮层规范。

### 2.2 不包含

- 嵌套画廊或画廊文件夹。
- 灵感画廊、作品集等显式类型字段。
- 图片级说明、来源链接、标签、评分或备注。
- 图片编辑、裁切、滤镜或复杂缩放工具。
- 剪贴板粘贴导入。
- 图片文件名搜索或 OCR。
- 视频、网页及其他资源类型。
- 静态 HTML 作品集导出、公开链接或云端发布。
- 与笔记附件共享统一媒体资产表。
- 在资源管理器中暴露 CoolNote 内部资源文件。
- 专业数字资产管理系统所需的十万级图片索引能力。

## 3. 已确认的产品规则

### 3.1 导航与工作区

“画廊”是与“小记”并列的独立一级入口，只因产品排序而位于“小记”下方。入口数量表示未删除画廊数。

进入画廊后，主侧边栏保持固定；第二栏显示可折叠的平级画廊列表；右侧显示当前画廊。画廊列表行显示名称和图片数量。没有画廊时显示创建引导；空画廊显示拖放区域及“选择图片”按钮。

### 3.2 画廊管理

点击画廊列表标题旁的新增按钮后，在列表末尾显示原地名称输入框。名称去除首尾空格后必须非空；允许不同画廊重名。确认后创建并打开新画廊，同时聚焦介绍编辑区域。

画廊支持原地重命名和拖拽排序。新画廊默认追加在列表末尾，编辑内容不会自动改变画廊位置。

删除整个画廊前必须使用 CoolNote 产品对话框二次确认。确认后画廊和其中的画廊图片立即从界面移除，并显示 8 秒 Toast 撤销入口。

### 3.3 名称与介绍

名称和介绍均可在画廊内容区原位编辑。介绍是支持换行的纯文本，不使用 Markdown 或富文本编辑器。介绍在停止输入 300ms 后自动保存，保存状态必须明确展示“保存中、已保存、保存失败”。

### 3.4 图片墙

图片墙保持原始宽高比并按横向行优先排列，每行最多三张，随可用宽度不足响应式降为两列或一列。图片使用缩略图加载，滚动接近当前数据尾部时增量加载下一页，不一次加载全部原图或挂载全部图片节点。

用户可拖拽调整图片顺序，新导入图片默认追加在末尾。GIF 在瀑布流中显示静态首帧和动态标识，避免多张动画同时解码；在灯箱中播放完整动画。

悬停单张图片时显示选择、删除和更多操作。普通浏览状态不长期显示复选框。

### 3.5 灯箱

点击图片打开应用内灯箱。灯箱支持：

- 上一张、下一张。
- 键盘左右方向键切换。
- Esc 或关闭按钮退出。
- 将图片内容写入系统剪贴板。
- 通过系统文件选择器另存为未经修改的原图。
- 移动到其他画廊。
- 复制到其他画廊。
- 删除当前画廊图片。

灯箱不调用系统默认图片查看器，不复制内部文件路径，也不提供图片编辑能力。

### 3.6 图片选择与批量整理

用户可进入临时批量选择模式，对选中图片执行删除、移动或复制。退出选择模式后恢复普通画廊展示。批量删除必须先使用产品对话框确认，完成后仍提供 8 秒 Toast 撤销。

“移动”在目标画廊建立关系后移除当前关系；“复制”保留当前关系并在目标画廊增加关系。目标画廊已有同一图片时，该项跳过并在结果中说明。移动操作遇到目标重复项时保留来源关系，不把“已存在于目标”误当成移动成功。

单张图片可从卡片悬停操作或灯箱菜单删除。单图删除不再弹出确认框，图片立即隐藏并提供 8 秒 Toast 撤销。

## 4. 技术方案

采用独立画廊子系统，不重构现有笔记附件模型。

React 画廊界面只能通过类型化 Tauri Commands 调用 Rust 应用服务。新增 `GalleryService` 负责画廊业务、数据库事务、路径安全、导入任务和资源清理。前端不得直接执行 SQL，也不得持有任意内部文件系统权限。

### 4.1 数据模型

新增 SQLite 迁移并建立以下概念表：

#### `galleries`

- 唯一 ID。
- 名称。
- 纯文本介绍。
- 人工排序值。
- revision。
- 创建时间和更新时间。
- 软删除时间及撤销操作标识。

#### `gallery_assets`

- 唯一 ID。
- 唯一内容哈希。
- 原始文件名。
- 媒体类型。
- 字节大小。
- 图片宽度和高度。
- 原图内部相对路径。
- 创建时间。

#### `gallery_items`

- 唯一 ID。
- 画廊 ID。
- 图片资产 ID。
- 在该画廊中的人工排序值。
- 创建时间。
- 软删除时间及撤销操作标识。

同一未删除画廊内，画廊 ID 与资产 ID 的组合必须唯一。一个图片资产可以被多个画廊图片引用。

### 4.2 去重边界

内容哈希去重覆盖所有画廊，但不跨越到现有笔记附件模块。同一图片加入不同画廊时只复用一个画廊图片资产；同一图片再次加入同一画廊时跳过并提示。

### 4.3 文件与缩略图

原图复制到 CoolNote 资料库内部的画廊资源目录，不保存对用户原始路径的长期依赖。用户移动或删除外部原文件后，画廊仍可使用。

缩略图按资产内容哈希生成到独立缓存目录。缩略图属于可重建派生数据，不是唯一事实源；丢失或损坏后可以从原图重新生成。GIF 缩略图使用静态首帧。

原图必须随资料库备份和迁移；缩略图可以重建，不承担恢复责任。

### 4.4 删除与物理清理

删除画廊或画廊图片先写入软删除状态。8 秒撤销窗口内不得物理删除原图。撤销窗口结束后，只有没有任何未删除画廊图片引用的资产才允许清理原图和缩略图。

软删除及撤销操作标识持久化到数据库。应用在撤销窗口内异常退出时，下次启动根据删除时间完成过期清理；不存在只依赖前端定时器的删除状态。

## 5. 数据流

### 5.1 读取

进入画廊入口时只读取画廊摘要列表。选中画廊后分页读取画廊图片关系和缩略图信息。灯箱接近当前分页边缘时预取后续数据。

摘要读取不得解码或读取原图。200 个画廊和 10,000 张总图片规模下，启动画廊入口不允许因扫描全部图片文件而阻塞。

### 5.2 名称、介绍与排序

名称和介绍通过独立命令保存。介绍写入携带当前 revision，服务端只接受基于当前 revision 的更新，成功后返回新 revision。

排序命令发送被移动对象及其前后相邻对象，由服务端在事务中计算和规范化排序值，不要求前端提交整个画廊或图片列表。新画廊和新图片默认追加到末尾。

### 5.3 导入

系统文件选择器和 Tauri 拖放事件将所选文件路径传给 Rust。大图片不得以整批 Base64 数据穿过前端 IPC。

单个文件的导入顺序为：

1. 规范化并校验输入路径。
2. 校验扩展名、MIME、实际内容、可读取性和 100 MB 上限。
3. 解码宽高等基本信息并计算内容哈希。
4. 检查当前画廊是否已存在相同资产。
5. 将新内容写入内部临时文件，完成校验后原子改名。
6. 在数据库事务中写入或复用资产记录，并追加画廊图片关系。
7. 生成缩略图并发送任务进度。

每个导入任务具有任务 ID 和取消标记。用户取消后，已经成功提交的图片保留，未开始的文件不再处理，当前安全检查点结束后停止。任务结束时汇总已添加、已跳过、未处理和失败数量。

### 5.4 复制、移动与批量操作

复制只创建新的画廊图片关系。移动在同一事务中创建目标关系并移除来源关系。批量删除、移动或复制统一在事务中提交；任一数据库写入失败时回滚该次批量关系变更，并由前端恢复服务端状态。

### 5.5 搜索

全局搜索索引画廊名称和介绍，不索引图片文件名，也不做 OCR。搜索结果类型显示为“画廊”，点击后切换到画廊入口并打开对应画廊。

## 6. 导入规则与容量

- 支持 JPEG、PNG、WebP、GIF。
- GIF 原始动画必须保留。
- 不支持 SVG、HEIC、AVIF。
- 单张图片最大 100 MB。
- 单次导入不设置图片张数上限。
- 导入必须显示进度并允许取消。
- 磁盘空间不足时停止后续导入。
- 单个文件失败不回滚已经成功的其他文件。
- 不支持的文件、损坏文件和读取失败文件必须显示具体原因。
- 当前画廊中的重复图片计为“已跳过”，不计为导入错误。

## 7. 错误处理与安全

### 7.1 文件原子性

新原图采用临时文件、完整校验、原子改名、数据库提交的受控流程。数据库不得引用半写入文件。数据库提交失败时，新产生且尚无引用的内部文件必须清理。

### 7.2 缩略图失败

缩略图失败不影响原图入库。界面显示明确占位状态并提供重试生成，不把缩略图失败伪装成整张图片导入失败。

### 7.3 原图缺失或损坏

内部原图缺失或损坏时保留画廊结构、顺序和原始文件信息，并显示“资源缺失”卡片。首版提供重新选择图片进行修复或移除该画廊图片，不静默删除记录。重新选择的内容哈希与原资产相同时修复共享资产；哈希不同时创建新资产，并且只替换当前画廊图片，不能悄悄改变其他画廊中的引用。

### 7.4 保存失败和冲突

介绍自动保存失败时保留前端草稿并持续显示失败状态和重试入口，不显示虚假的“已保存”。revision 冲突不得自动覆盖数据库内容；界面保留本地草稿并读取最新服务端 revision，随后让用户明确选择“使用服务端版本”或“用本地草稿覆盖”。

### 7.5 剪贴板与另存为

复制图片失败、另存为失败和系统权限错误通过 Toast 明确提示。用户主动取消文件选择或另存为属于正常结束，不显示错误。

### 7.6 路径安全

所有外部和内部路径均需规范化并校验最终范围。不得接受路径穿越，不得通过前端暴露内部真实路径。文件格式同时检查扩展名、MIME 和实际内容，不能只信任扩展名。

## 8. 前端组件边界

- `GalleryWorkspace`：协调当前画廊、折叠状态、保存状态和全局操作。
- `GallerySidebar`：画廊摘要列表、原地创建、重命名、排序和删除。
- `GalleryHeader`：名称、介绍、添加图片、选择模式及画廊菜单。
- `GalleryMasonry`：瀑布流、分页、缩略图、图片排序和空状态。
- `GallerySelectionBar`：批量删除、移动、复制、全选和退出选择模式。
- `GalleryImportProgress`：任务进度、取消和结果汇总。
- `GalleryLightbox`：完整查看、前后切换、复制、另存为、移动、复制和删除。

组件沿用 CoolNote 现有 Icon、FloatingLayer、ProductDialog、ProductToast 和全局 Tooltip。不得使用浏览器原生 `prompt`、`confirm` 或未设计的菜单。所有图标按钮必须有可访问名称，最高层浮层响应 Esc 并把焦点返回触发对象。

画廊的成功、错误、导入结果和撤销反馈必须全部通过应用层共享 `ProductToast` 触发，不允许在画廊功能目录中新增独立 Toast 或固定定位错误条。若现有 Toast 缺少语义，应扩展共享组件，而不是在画廊内重复实现。

当桌面 WebView 的拖放 `File` 对象不提供非标准本地 `path` 时，前端按文件逐个读取并调用数据导入命令；系统文件选择器仍优先走路径导入。该兼容分支不得再次提示用户改用“添加图片”。

## 9. 视觉与可访问性

- 延续当前 CoolNote 产品原型的侧栏尺寸、层级、间距、颜色和动效语言。
- 画廊列表可折叠，折叠后内容区获得释放宽度。
- 瀑布流不裁切缩略图的主体比例。
- 普通浏览状态不长期显示选择框和全部操作。
- 支持浅色、深色和 `prefers-reduced-motion`。
- 新建、重命名、添加、选择、灯箱、删除和关闭均具备键盘路径。
- 拖拽排序之外必须提供“前移一位、后移一位、移到开头、移到末尾”菜单操作，以便键盘用户调整画廊和图片顺序。
- 目标窗口宽度为 1024px 及以上，并在 1440×900 进行主要视觉验收。

## 10. 性能与容量目标

首版设计和验收规模为：

- 最多约 200 个画廊。
- 总计约 10,000 张图片。
- 单个画廊最多约 2,000 张图片。

为达到该规模：

- 画廊摘要不得加载原图。
- 图片列表必须分页或增量加载。
- 原图只在灯箱或明确需要时加载。
- 瀑布流使用缩略图且不一次挂载全部节点。
- GIF 在瀑布流中不得自动播放。
- 大批量导入期间界面必须持续报告进度并可取消，不得长时间无反馈。

十万张以上图片、专业级索引和完整数字资产管理不属于本次范围。

## 12. 完成定义

本次画廊功能只有同时满足以下条件才算完成：

- 用户可以创建、重命名、介绍、排序和删除真实画廊。
- 用户可以选择或拖入真实图片，重启应用后内容仍存在。
- 图片可按人工顺序以瀑布流展示，并可在灯箱完整浏览。
- 复制图片、另存为、移动、复制、删除及批量整理均可用。
- 画廊之间复用图片时不会重复保存物理文件。
- 导入部分失败、取消、磁盘问题、缩略图失败和资源缺失均有明确且不丢失既有数据的行为。
- 删除具备持久化软删除和 8 秒撤销，不依赖单纯前端状态。
- 全局搜索可以通过名称和介绍定位画廊。
- 约定容量下采用缩略图、分页和有限挂载，不一次加载全部原图。
- 自动化测试、构建检查和真实 Tauri 人工验收全部通过。
- 原有笔记和小记行为没有阻断性回归。

## 13. 实施边界与升级条件

实施必须保持本设计的独立子系统边界。若开发中发现必须重构现有笔记附件表、引入全应用媒体资产库、恢复完整桌面 E2E、增加视频或网页资源、加入公开发布，均视为隐藏复杂度和范围升级，必须停止实施、重新归类并获得用户再次批准。
